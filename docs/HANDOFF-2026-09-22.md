## 1. À lire avant de toucher au code, dans cet ordre

1. **`CLAUDE.md`** — source de vérité : couches, invariants du thread audio, contrats de
   persistance, règle de livraison (build + liste de tests numérotée à chaque build installé).
2. **`TODO.md`** (uniquement ce qui reste à faire ou est en cours, `- [~]` = en cours) et
   **`DONE.md`** (archive). La skill `/matodo` gère les deux ; règle : jamais une tâche cochée
   dans `TODO.md`.
3. **`CHANGELOG.md`** — une entrée par build installé, la plus récente en haut. Chaque entrée
   dit ce qui a été mesuré, pourquoi, et ce qui reste. C'est l'historique fin de tout ce qui
   suit.
4. **`.claude/skills/nouvel-instrument/SKILL.md`** — la procédure exécutable pour ajouter un
   instrument (trois espaces d'index, contrats, étapes ordonnées). `ADDING_AN_INSTRUMENT.md`
   est le document d'architecture qui pointe dessus.
5. **`docs/design/UI-REDESIGN-HANDOFF.md`** avant tout travail dans `src/ui/`.

**`docs/notes/notes.txt` est le carnet personnel de NicoM. Lecture seule, absolue.** Il y note
ses idées ; on les ticketise dans `TODO.md` quand il le demande, on n'y écrit jamais (sept notes
ont été effacées le 2026-09-13 par une « ticketisation » : à ne jamais reproduire).

## 5. Comment travailler avec NicoM (appris, parfois durement)

- **Il valide chaque build à la main dans Studio One**, parfois REAPER. Chaque build installé
  se termine par une liste numérotée « À tester dans Studio One (build <ID>) » : une action
  par ligne, le libellé exact à l'écran, le résultat attendu, la régression à guetter.
- **Studio One verrouille le DLL.** Vérifier `Get-Process "Studio One"` avant `-Install`. S'il
  est ouvert : `.\build.ps1` (compile + bundle, sans installer), lui dire de fermer S1, et
  installer quand il répond « s1 fermé ». Ne pas demander « ok ? » avant un build : lancer.
  Chaque `build.ps1` recompile avec un nouveau Build ID, le CHANGELOG cite celui du build
  **installé**.
- **Ses messages sont brefs.** « c'est bon » = validé, « next » / « on continue » = présenter
  la liste des tâches ouvertes par priorité et attendre son choix (règle de `CLAUDE.md`), ne
  pas coder. Un « 0 » ou un « 1 » isolé est une frappe accidentelle. Il fait plusieurs choses
  en parallèle : chaque message doit se lire seul, redire en une ligne de quoi il s'agit.
- **Faire exactement le périmètre demandé.** Le 2026-09-21, « griser et décaler les
  sous-paramètres de la saturation… pour tous les sous-paramètres » a été généralisé à tout
  le panneau avec une barre verticale : rejeté net (« c'est n'importe quoi, rien n'est
  cohérent »), retiré au build suivant. Si une extension paraît logique, la proposer en une
  ligne, ne pas la livrer. Aucun ornement visuel non demandé. Idem pour les idées du TODO :
  proposer, pas implémenter d'office.
- **Ses demandes explicites passent avant le plan.** Le build 3 de Rift a été fait avant
  ses demandes ticketées sur Advance : reproche justifié.
- **Mesurer avant de corriger, et chiffrer le rapport.** Les bugs de cette période ont tous
  été résolus par une mesure (rendu de test, journal, balayage de texture) : clic de fin de
  coup (résidu −0,00097 coupé en un échantillon), « fausse enveloppe de pitch » (balayage de
  filtre 6,5 → 1,2 kHz + zone rugueuse à l'offset 0,25), Offset inerte sur sample court
  (réserve de quatre decays), clavier REAPER (trace `FLASH_DRUM_KBD_LOG=1`). Quand il dit

- **Quand il signale qu'un correctif « a encore sauté »**, vérifier d'abord que le build qui

## 6. Pièges techniques récents, avec les endroits du code

- **Jamais de dialogue modal dans l'image egui.** `rfd::FileDialog::pick_file()` appelé dans
  `ui()` a fait tomber Studio One (re-entrée de la boucle de messages baseview → panic →
  `panic = abort`). Modèle à suivre : `TexturePick` (`editor_state.rs`) + thread dédié +
  `poll_texture_pick` (`sound_editor.rs`).
- **Un `IntParam` `.hide()` est lecture seule pour l'hôte** : pendant la lecture, un changement
  fait dans l'interface passe par l'hôte, qui le refuse. Les params par slot (`advmode_N`,
  `page_loop`) sont donc visibles.
- **Déplacer une lane** (`grid.rs`, `apply_lane_reorder_move`) permute **tous** les magasins
  par slot : pattern, fusions, sons, p-locks, seq-plocks, params (mute/solo/mix/algo/humanize/
  push/length), verrous de longueur, et depuis [228] les textures (`UserTextures::reorder`).
  Tout nouveau magasin par slot doit y être ajouté.
- **Thread audio** : `TexturePool` (`sample_bank.rs`) se lit par un load atomique + clone
  d'`Arc` ; la génération précédente est parquée côté UI pour ne jamais libérer sur le thread
  audio. `Voice::set_texture_pool(pool, lane)` et `Voice::set_hit_index(n)` sont appelés par
  le plugin avant `trigger()`.
- **Fin de coup** : chaque point de coupure d'une voix doit passer par un fondu
  (`RiftVoice::cut()` arme le `RetrigDeclick` par canal). Contrat de retrigger [179] : état
  neuf + declick 3 ms, jamais de phase continue.
- **Séquenceur / boucle de page** : la position maître est bornée par `loop_bounds()` ; un
  saut (engagement, retour de page) recale les compteurs des lanes (`expected` vs
  `shifted_master`), la synchro hôte passe par `host_to_local`. Un wrap de pattern compte
  comme un retour de page.
- **Persistance** : nouvelles clés `lane-textures-v1` (14 chemins), params `advmode_1..14`,
  `page_loop`. Les clés `user-textures-v1` et `auto_out` des builds intermédiaires ne sont
  plus lues. Les contrats positionnels de `CLAUDE.md` restent intouchés.
- **Clavier Windows** (`vendor/nih-plug/nih_plug_egui/src/editor.rs` module `win_keyboard`,
  `vendor/nih-plug/src/wrapper/vst3/view.rs`) : lire l'entrée CHANGELOG du 2026-09-14 [229]
  avant d'y toucher ; le journal `%TEMP%\flash_drum_kbd.log` (`FLASH_DRUM_KBD_LOG=1`) a
  tranché chaque étape.
- **Panneau Sons** : sections par `ParamFamily` (Osc = « Texture » / « Sample » /
  « Oscillator » selon l'instrument, Pitch, Amp, Filter, Modulation, Saturation affichée
  « Distortion »), rangées « hissées » sous une rangée standard (Resonance sous la coupure,
  Filter Attack/Hold sous Filter Env), interrupteur générique pour tout paramètre discret 0/1
  sans liste, dropdown générique via `SpecialParamDef.options`.
- **Scripts de patch** : le travail s'est fait par scripts Python appliquant des
  remplacements exacts ; ils vivent dans le scratchpad de la session, pas dans le dépôt. Un
  antislash de continuation dans un littéral Rust écrit par script est un piège connu.
